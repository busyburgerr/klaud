# Клауд — backend

REST API каталога частных объявлений. Node.js + Express 5 + SQLite (`node:sqlite`,
без нативных сборок). Фронтенд (`src/`) работает целиком на этом API — статических
данных в приложении не осталось.

## Разработка

Два процесса: Vite для фронтенда и Express для API.

```bash
pnpm install
pnpm run api      # терминал 1 — API на :3001
pnpm run dev      # терминал 2 — фронтенд на :8443
```

Первый запуск создаёт `data/cloud.db` и наполняет её демо-каталогом. Vite
проксирует `/api` и `/uploads` на API, поэтому фронтенд ходит по относительным
путям — как и в проде.

## Продакшен

Один процесс отдаёт и API, и собранный фронтенд:

```bash
pnpm build
NODE_ENV=production JWT_SECRET=<секрет> pnpm start
```

Сервер поднимается на `PORT` (или `API_PORT`, по умолчанию 3001), раздаёт `dist/`
с SPA-fallback — прямые ссылки вида `/lot/12` и обновление страницы работают.
Без заданного `JWT_SECRET` в проде запуск прерывается: с дефолтным секретом любой
может подписать себе токен.

Секрет генерируется так:

```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```

Что нужно вынести на постоянные тома при деплое: `data/` (база) и
`server/uploads/` (фотографии лотов).

| Команда | Что делает |
| --- | --- |
| `pnpm start` | Прод: API + раздача `dist/` |
| `pnpm run api` | Запуск API (dev) |
| `pnpm run api:dev` | То же с перезапуском при изменении файлов |
| `pnpm run api:seed` | Наполнить пустую базу демо-данными |
| `pnpm run api:seed -- --force` | Пересоздать демо-данные с нуля |
| `pnpm run api:reset` | **Очистить базу**: остаются только категории и персонал |
| `pnpm run api:test` | Прогнать тесты API (66 проверок, своя временная база) |

### Состояние базы

`pnpm run api:reset` приводит базу к рабочему минимуму: справочник из десяти
категорий и две учётные записи персонала. Лоты, материалы журнала, диалоги,
избранное, жалобы и журнал модерации удаляются. С таким состоянием площадку
можно открывать для настоящих пользователей.

В этом режиме витринные счётчики из макета обнуляются, и сайт показывает
только настоящие числа: пока лотов нет, бегущая строка говорит «Каталог открыт
для первых лотов», а не рисует миллион объявлений.

Файлы в `server/uploads/` командой не трогаются — удаляйте их отдельно, если
нужно убрать фотографии удалённых лотов.

## Авторизация

Вход по номеру телефона и паролю. Номер нормализуется до 10 цифр, так что
`+7 900 128-45-09`, `8 (900) 128-45-09` и `9001284509` — один и тот же аккаунт.

Токен возвращается в теле ответа **и** ставится в httpOnly-cookie. Клиент может
использовать любой способ: `Authorization: Bearer <token>` или cookie.

#### Формат материала

Тело материала — массив блоков, а не сплошной текст:

| Блок | Поля | Как выглядит |
| --- | --- | --- |
| `paragraph` | `text` | обычный абзац |
| `heading` | `text` | подзаголовок раздела |
| `list` | `items: [text]` | маркированный список |
| `steps` | `items: [{ title, text }]` | нумерованная инструкция 01, 02, 03 |
| `callout` | `label`, `text` | тёмная врезка с подписью |

```json
{ "title": "Безопасная сделка", "rubric": "Покупателям", "body": [
  { "type": "paragraph", "text": "Между вами и продавцом стоит платформа." },
  { "type": "heading", "text": "Как работает эскроу" },
  { "type": "steps", "items": [{ "title": "Оплата замораживается", "text": "Деньги идут на счёт Клауд." }] },
  { "type": "list", "items": ["Просьба перевести на карту."] },
  { "type": "callout", "label": "Важно", "text": "Оплата — только внутри Клауд." }
]}
```

Пустые блоки и пустые пункты отбрасываются при сохранении. Ошибка в теле
указывает номер блока: `{"body": "Блок 2: Подзаголовок длиннее 200 символов"}`.
Материалы старого формата (массив строк) читаются как последовательность
абзацев — миграция не нужна.

Адрес материала получается из заголовка транслитерацией и при правке не меняется —
ссылки не ломаются. Время чтения считается по объёму текста, лид при отсутствии
берётся из первого абзаца. Черновики не попадают в список для читателей, а прямая
ссылка на черновик отдаёт `404` всем, кроме редакции. Ответы `/api/articles`
содержат `canEdit` — по нему интерфейс показывает кнопки редакции.

## Формы ответов

Ошибки — всегда `{ error, details? }`, где `details` разбит по полям формы:

```json
{ "error": "Проверьте заполнение полей", "details": { "title": "Минимум 4 символов" } }
```

Списки — `{ items, total, page, limit, pages }`.

Лот приходит готовым к вёрстке: `price` — строка `"28 500"` (число отдельно, в
`priceValue`), `time` — возраст словами (`"1 ч"`, `"вчера"`, `"2 дн"`), `img` —
первая фотография. Поле `wished` заполняется, если запрос авторизован.

Подписи времени (`time` у лота, `time` у сообщения) формируются в часовом поясе
сервера. Если клиенту нужен свой пояс — форматируйте из `createdAt`.

## Модерация

Жизненный цикл лота: `pending` → `active` (одобрен) или `rejected` (отклонён с
причиной). Владелец видит причину отказа в кабинете, исправляет лот и отправляет
его на повторную проверку.

Сам себе опубликовать лот продавец не может: `PATCH /api/listings/:id`
принимает от владельца только статусы `sold` и `archived`. Больше того, правка
содержимого уже опубликованного лота возвращает его в очередь — иначе одобренное
объявление можно было бы переписать во что угодно после проверки.

Блокировка аккаунта закрывает вход и снимает с публикации все активные лоты
продавца. Каждое действие персонала пишется в `moderation_log` с автором,
причиной и временем — включая работу с материалами журнала.

Модераторы и администраторы ведут журнал: пишут материалы, правят их, держат
черновики и удаляют. Отдельной роли редактора нет — права те же, что у модерации.

## Ограничения, о которых стоит знать

- **Сообщения — опрос, не push.** Открытый диалог опрашивает `?after=` раз в 5 с.
  Для нагрузки стоит перейти на WebSocket/SSE.
- **Фотографии лежат на диске** (`server/uploads/`). При нескольких инстансах
  нужен общий том или объектное хранилище (S3).
- **Лимитер запросов — в памяти процесса.** При горизонтальном масштабировании
  считать лимиты нужно в общем хранилище (Redis).
- **Уведомления не отправляются.** Переключатели в настройках сохраняются, но
  почта и пуши не подключены.
- **`secure`-cookie включается автоматически при `NODE_ENV=production`** — то есть
  сайт должен работать за HTTPS, иначе cookie не установится (токен из
  localStorage продолжит работать).
